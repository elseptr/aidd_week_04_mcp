# Техническое задание для AI-агента: разработка skill `make_report`

## 1. Цель работы

Необходимо создать skill `make_report` для Qwen Code, который автоматизирует формирование аналитического отчёта в формате XLSX версии 1.1.

Skill должен состоять из двух основных частей:

1. Детерминированная часть — Python-скрипт, который получает исходные данные, рассчитывает статистические показатели и формирует XLSX-файл.
2. Инструкция для агента — файл `SKILL.md`, содержащий описание назначения skill и порядок его использования.

Главное требование: все вычисления и формирование Excel-файла должны выполняться Python-скриптом, а не непосредственно языковой моделью. Агент должен только определить, когда применять skill, найти необходимые данные и запустить скрипт.

## 2. Структура проекта

Создать следующую структуру:

```text
practice/
└── agent/
    └── .qwen/
        └── skills/
            └── make_report/
                ├── SKILL.md
                ├── make_report.py
                └── tests/
                    └── test_make_report.py
```

Не изменять остальные файлы проекта без необходимости.

Если в репозитории уже существуют тесты, примеры отчётов, спецификации формата 1.1 или исходные данные, сначала изучить их и использовать в качестве основного источника требований.

## 3. Этап 1. Изучение проекта

До написания кода агент должен:

1. Изучить структуру репозитория.
2. Найти описание формата отчёта XLSX версии 1.1.
3. Найти примеры ранее сформированных отчётов, если они существуют.
4. Определить, откуда должны поступать исходные данные.
5. Выяснить:
   - обязательные поля;
   - типы данных;
   - правила обработки пропусков;
   - формулы статистических показателей;
   - структуру итоговой книги Excel;
   - требования к названиям листов и столбцов;
   - форматирование ячеек;
   - требования к итоговому имени файла.

Не выдумывать отсутствующие требования. Если спецификация не найдена, зафиксировать это и реализовать только те правила, которые подтверждаются исходными материалами проекта.

## 4. Этап 2. Реализация Python-скрипта

Создать `make_report.py`.

### 4.1. Общие требования

- Python 3.
- Использовать `openpyxl` для создания XLSX.
- Для обработки табличных данных допустимо использовать `csv` и стандартную библиотеку Python.
- Не использовать LLM для вычислений.
- Не использовать случайные значения и недетерминированные алгоритмы.
- При одинаковых входных данных скрипт должен формировать одинаковые значения статистики и одинаковую структуру отчёта.
- Разделить чтение данных, расчёт статистики и генерацию XLSX на отдельные функции.

### 4.2. Интерфейс запуска

Предусмотреть запуск из командной строки:

```bash
python make_report.py --input <путь_к_данным> --output <путь_к_отчёту>
```

Дополнительно предусмотреть:

```bash
python make_report.py --help
```

Требования:
- `--input` — путь к исходным данным.
- `--output` — путь сохранения итогового XLSX.
- Проверять существование входного файла.
- Проверять корректность формата входных данных.
- При ошибке выводить понятное сообщение в stderr.
- При успешном выполнении возвращать код завершения 0.
- При ошибке возвращать ненулевой код завершения.
- Не перезаписывать исходные данные.
- Если выходная директория отсутствует, создавать её автоматически.

Формат входных данных необходимо определить по материалам проекта. Не добавлять неподтверждённые обязательные поля.

### 4.3. Чтение и проверка данных

Реализовать отдельную функцию загрузки данных.

Она должна:
- корректно читать входной формат;
- проверять наличие обязательных полей;
- проверять типы значений;
- обнаруживать некорректные числовые значения;
- корректно обрабатывать пустые значения согласно спецификации;
- не изменять исходный файл;
- сообщать, в какой строке обнаружена ошибка, если это возможно.

Не допускать молчаливого преобразования некорректных данных в нули.

### 4.4. Расчёт статистики

Реализовать отдельную функцию расчёта статистики.

Включить все показатели, которые требуются форматом 1.1 и подтверждаются спецификацией проекта.

В частности, проверить наличие требований к следующим показателям:

- количество записей;
- количество корректных и некорректных записей;
- сумма;
- среднее арифметическое;
- минимум;
- максимум;
- медиана;
- стандартное отклонение;
- количество пропусков.

Этот список не является разрешением самостоятельно добавлять все показатели в итоговый отчёт. В XLSX должны попадать именно те показатели и в том виде, которые предусмотрены форматом 1.1.

Для каждого показателя:
- определить точную формулу;
- правильно обрабатывать пустые выборки;
- исключить деление на ноль;
- не допускать некорректных результатов при отсутствии данных;
- использовать согласованную точность округления.

Все вычисления должны быть воспроизводимыми.

### 4.5. Формирование XLSX

Создать отдельную функцию генерации Excel-книги.

Обязательно соблюдать формат 1.1:
- названия листов;
- порядок листов;
- названия столбцов;
- порядок столбцов;
- типы значений;
- форматы чисел и дат;
- расположение статистики;
- оформление заголовков;
- объединение ячеек, если оно предусмотрено;
- формулы или сохранённые значения согласно спецификации.

Не добавлять лишние листы и столбцы, если формат этого не предусматривает.

Файл должен открываться стандартными средствами работы с XLSX.

При необходимости применять:
- жирное начертание заголовков;
- ширину столбцов;
- закрепление заголовков;
- фильтры;
- числовые форматы;
- выравнивание.

Но оформление должно соответствовать существующему образцу или требованиям формата 1.1.

### 4.6. Обработка ошибок

Предусмотреть обработку следующих ситуаций:

- входной файл отсутствует;
- входной файл пуст;
- отсутствуют обязательные столбцы;
- неверный формат входных данных;
- некорректные числовые значения;
- повреждённый XLSX, если он является допустимым входным форматом;
- отсутствует возможность записать выходной файл;
- недостаточно данных для отдельных статистических показателей.

Ошибки не должны приводить к созданию внешне успешного, но некорректного отчёта.

Если генерация завершилась ошибкой, не оставлять частично сформированный итоговый файл под окончательным именем.

## 5. Этап 3. Создание SKILL.md

Создать файл:

`practice/agent/.qwen/skills/make_report/SKILL.md`

В начале файла обязательно должен находиться YAML frontmatter:

```yaml
---
name: make_report
description: Создаёт аналитический XLSX-отчёт формата 1.1 по исходным данным. Используй этот skill, когда требуется рассчитать статистические показатели и сформировать Excel-отчёт.
---
```

Далее написать короткую и однозначную инструкцию для агента.

Инструкция должна содержать следующие разделы.

### Назначение

Объяснить, что skill нужен для детерминированного формирования XLSX-отчётов версии 1.1.

### Источник данных

Указать:
- где искать исходные данные;
- какие файлы использовать;
- как определить подходящий входной файл;
- что делать, если входные данные отсутствуют или неоднозначны.

Не придумывать пути: использовать фактическую структуру проекта.

### Запуск

Привести пример команды:

```bash
python .qwen/skills/make_report/make_report.py \
    --input <путь_к_данным> \
    --output <путь_к_отчёту>
```

Если рабочая директория отличается, использовать корректный относительный или абсолютный путь.

### Результат

Указать:
- куда сохраняется отчёт;
- как называется выходной файл;
- что файл должен иметь расширение `.xlsx`;
- что исходные данные не должны изменяться.

Выходной путь должен соответствовать требованиям проекта. Если конкретный каталог не задан, использовать согласованный каталог результатов, а не сохранять отчёт рядом с исходными данными без необходимости.

### Проверка результата

Агент после запуска должен:
1. Проверить код завершения скрипта.
2. Убедиться, что итоговый XLSX существует.
3. Проверить, что файл открывается через `openpyxl`.
4. Проверить наличие обязательных листов и столбцов.
5. Убедиться, что рассчитанные показатели присутствуют.
6. При наличии тестов запустить их.

Важно: инструкция должна быть короткой. Не копировать всю реализацию скрипта в `SKILL.md`.

## 6. Этап 4. Автоматические тесты

Создать:

`tests/test_make_report.py`

Использовать `pytest` и временные директории `tmp_path`.

Тесты должны проверять не только успешное создание XLSX, но и корректность вычислений, структуру книги и обработку ошибок.

### 6.1. Тесты расчёта статистики

**Тест 1. Обычный набор данных**

Взять небольшой заранее известный набор данных.

Проверить:
- количество записей;
- сумму;
- среднее;
- минимум;
- максимум;
- медиану;
- остальные предусмотренные спецификацией показатели.

Ожидаемые значения рассчитать вручную и явно записать в тесте.

**Тест 2. Один элемент**

Проверить, что статистика для набора из одной записи рассчитывается корректно.

**Тест 3. Пустой набор**

Проверить поведение при отсутствии записей. Скрипт не должен падать из-за деления на ноль.

**Тест 4. Одинаковые значения**

Использовать набор, состоящий из одинаковых чисел. Проверить корректность всех применимых показателей.

**Тест 5. Отрицательные значения и нули**

Проверить корректность статистики при наличии отрицательных чисел и нулей, если такие значения допустимы спецификацией.

**Тест 6. Пропущенные значения**

Проверить правила обработки пропусков и соответствующие счётчики.

### 6.2. Тесты валидации

**Тест 7. Отсутствие обязательного поля**

Ожидается понятная ошибка валидации.

**Тест 8. Некорректное числовое значение**

Например, вместо числа передать текст в числовом поле.

Скрипт должен сообщить об ошибке, а не подставлять 0.

**Тест 9. Отсутствующий входной файл**

Ожидается ненулевой код завершения CLI.

**Тест 10. Пустой входной файл**

Проверить, что поведение соответствует спецификации.

**Тест 11. Неверный формат входного файла**

Проверить корректную обработку неподдерживаемого формата или повреждённых данных.

### 6.3. Тесты XLSX

**Тест 12. Создание файла**

После выполнения генерации файл должен существовать и иметь расширение `.xlsx`.

**Тест 13. Открытие файла**

Открыть созданный файл через:

```python
from openpyxl import load_workbook
```

Убедиться, что книга успешно загружается.

**Тест 14. Структура листов**

Проверить точные названия и порядок листов по спецификации 1.1.

**Тест 15. Заголовки**

Проверить названия, порядок и количество столбцов.

**Тест 16. Значения**

Считать несколько ячеек с рассчитанной статистикой и сравнить их с ожидаемыми значениями.

**Тест 17. Форматирование**

Проверить наличие обязательного форматирования, если оно описано в спецификации.

**Тест 18. Отсутствие частичного отчёта**

Сымитировать ошибку записи и проверить, что повреждённый итоговый файл не остаётся под окончательным именем.

### 6.4. Тесты CLI

**Тест 19. Успешный запуск**

Выполнить скрипт через `subprocess.run` с корректными аргументами.

Проверить:
- код возврата 0;
- наличие выходного файла;
- возможность открыть XLSX.

**Тест 20. Некорректные аргументы**

Проверить запуск без обязательных аргументов.

Ожидается ненулевой код завершения и понятное сообщение об использовании.

**Тест 21. Создание выходной директории**

Передать путь к несуществующей выходной директории. Проверить, что она создаётся автоматически и файл сохраняется.

## 7. Требования к качеству кода

- Использовать понятные названия функций и переменных.
- Не создавать одну чрезмерно большую функцию.
- Не дублировать вычисления.
- Добавить type hints.
- Использовать `pathlib.Path` для работы с путями.
- Добавить docstrings к основным функциям.
- Не подавлять исключения без необходимости.
- Не использовать глобальное изменяемое состояние.
- Не хардкодить абсолютные пути к проекту.
- Не включать тестовые данные в основной отчёт.
- Не изменять исходные данные.
- Не добавлять ненужные зависимости.

8. Проверить, что скрипт можно запустить из корня репозитория.

Если в проекте используется другой способ запуска тестов или управления зависимостями, придерживаться существующих соглашений проекта.
